# 实施进度

当前已采用 `QCopilots-Search` 仓库规范命名和 `qcs-gui` 程序命名，工程、推理和提取、服务和检索、Qt 桌面应用、开发脚本及四组合 CI 已有实现，正在完成跨平台与发行候选验收。完整交付门槛尚未全部通过，语义相关性已有实际失败证据，当前生产语义候选关闭，文件浏览与关键词检索可用。

日常本地 `test`、`check` 和普通 PR 使用 `fast` 范围，保留 GUI、进程、存储、提取和工具回归，包含验收运行器的 `pure` 合约测试。真实模型、语义质量、容量及验收运行器的 `native` 慢测试保留在显式 `full` 范围中。快速报告中的排除项为未运行，本轮最终交付仍需完整验收，不因日常流程提速而减少门槛。

本文件描述实现边界，不追记每次运行的通过计数。实际结论以绑定不可变源码提交、程序和安装包 SHA-256 的新报告、CI artifact 及 [草稿 PR #1](https://github.com/xiaobing318/QCopilots-Search/pull/1) 中的证据为准。不能将取得报告后的 HEAD 追认为执行来源，也不能通过修改报告名称把旧执行归入新候选。

## 短命名与清理范围

自有程序、真实 CMake target、脚本、安装资源和生成目录采用 `qcs` 前缀。仓库规范名称及 URL 使用 `QCopilots-Search`，GUI 目标和可执行文件使用 `qcs-gui`，macOS 应用包使用 `qcs-gui.app`。不保留旧 GUI 命令别名。产品显示名称、现有 `qcs` profile 路径、C++ 命名空间 `qcopilots_search` 和 `QCOPILOTS_SEARCH_*` 配置接口保持不变。模型指纹、协议和二进制格式中的非路径标识继续保持稳定。

旧长命名候选的日志、截图、报告、构建树、缓存和安装包已退出本轮验收范围，并属于经授权清理的对象。清理操作是否完成以本轮清理记录为准，本文不提前声明已经删除。模型经锁定大小与 SHA-256 校验后保留，Qt 和外部工具链不属于清理范围。仍需维护的外置运行器应先整理入仓库，再删除旧副本。

新候选使用全新的外置构建目录和独立运行配置，不复用旧 CMake 二进制缓存，不自动迁移旧用户配置或索引。说明中的路径相对于调用者指定的外置根，不要求其他电脑使用相同盘符、用户名或源码位置。

## 已纳入实现的修复

以下内容说明继续保留的修复原因，不代表短命名候选已经复测通过：

- 检索采用更高的 ANN 查询预算、可索引的目录字面范围条件及按文件聚合的最近结果，回应先前容量测试暴露的召回与过滤问题。完整百万规模流程仍须重跑。
- 平台部署修复包括 Linux PNG/ZLIB 链接、macOS 依赖与 CPU 模块布局、模型目录容量查询及 NSIS UTF-8 参数。每个平台仍须取得本轮原生构建和最终包验证。
- 工具链修复保留 MSVC Unicode response file 与 JPEG 消费者目录直接生成源文件的方式。缩短名称不能替代字符编码、头文件顺序或 ABI 检查。
- 开发脚本将 NSIS 准备延迟到需要该生成器的 Windows `package` 阶段，日常 Qt bootstrap 和 fast 构建测试不再准备安装器工具。安装包与源码材料仍需对应同一候选的实际验证。

语义语料属于受控实施验收集，不是独立人工盲评。自然照片、声音和视频样本的覆盖有边界，不能推广为所有题材或口音的质量保证。原 96 条无答案查询没有语音或环境音负例，新录音负例补充了此前缺失的同模态困难条件。中英文查询也不代表中文语音或多口音覆盖，当前音频片段没有转写文字。

第二版校准工具、配套测试、固定分组和完整语料生成器均已接入。实际完成了 186 文件、1,364 个真实向量的提取与采样，以及开发交叉验证、完整开发拟合和新 40 主题的首次独立评估。首次独立评估的总体召回为 72/80，但代码召回 17/24 和无答案误返回 14/80 未达到标准。[固定失败报告](../tests/semantic/calibration/qcs-relevance-v2-quarter-aa26a4593aa2-holdout-failed.json) 保留原始结论，详见 [语义验收说明](../tests/semantic/README.md)。

后续把全部已观察的 318 条正例和 176 条无答案查询作为 development，按预先固定的 54 个主题家族做三折交叉验证。以下有限机制对照使用 10% 训练误返回上限，OOF 仍要求总体召回至少 90%、各语言和内容模态至少 80%、无答案误返回至多 10%。此前 5% 训练上限只是内部保守协议，其失败证据同样保留。

## 完成门槛

所有必需证据必须对应同一冻结候选。本地 Windows 完整自动化测试、远端四组合原生 CI 和最终 Windows 包的 Computer Use 是三个独立门槛，不能相互替代。

| 门槛 | 本轮必需证据 | 当前发布判断 |
| --- | --- | --- |
| 本地自动化 | 完整 CTest、QtTest 和工具测试，真实模型、路径及清理回归、安装验证，注册清单与逐用例明细一致 | 以新候选报告判定，未取得完整证据前不通过 |
| 语义质量 | 冻结策略及真实生产检索的总体 Recall@10 至少 90%、各语言和内容模态至少 80%、独立无答案误返回率至多 10% | V2 首次独立评估及后续有限开发对照失败，生产语义候选关闭 |
| 四组合原生 CI | 显式 `full` 运行中 Windows x64、Linux x64、macOS arm64 和 x64 的构建、测试、真实模型、包验证与汇总 job 全部实际 success | `fast` 成功或触发完整工作流都不等于完整通过 |
| Windows Computer Use | 同一最终包的 CU-01 至 CU-10，独立 profile、实际操作、截图及逐场景包和程序哈希 | 未运行或工具无法覆盖的必需场景阻断完成 |
| 容量与恢复 | 十万物理文件、百万 768 维向量写入与重载、精确对照、过滤、500 次计时、后台单分片重建、增删改及故障恢复 | 不能用小规模 CI 或历史参数探针替代 |
| 发布材料 | ZIP/NSIS、分架构 DMG、TGZ/DEB、对应源码、许可证、符号、校验和及签名状态 | 与实际包和提交绑定后验收 |

通过、不适用、失败和未运行分别记录。Windows 的大小写敏感路径专用用例可以按严格匹配规则记为不适用，但缺模型、权限或材料不能沿用这一分类。来源失配、必需用例缺失、清理失败和残留进程都需要明确失败。

每轮执行先保存来源清单，再运行测试或用户操作，结束后校验附件。原生 CI 分别记录 PR head 和实际 checkout，最终本机包与其候选、源码树和依赖锁对应。只有全部必需门槛满足后才能标记实施完成，合并和公开发布仍由用户决定。
