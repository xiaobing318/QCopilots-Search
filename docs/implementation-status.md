# 实施进度

本轮在 `codex/qcopilots-search-v1` 分支增量实施，调研基线为 QCopilots-Search `bf60aec`，参考 DigUp 本地 `main` 的 `6faa29e`。继续使用 C++20、Qt Widgets、CMake 和 GUI、服务、worker、CLI 架构。DigUp 参考仓库不修改，开发分支不提前合并到 `main`。

本文记录实现范围及完成条件，不把存在源码、触发工作流或历史候选通过当作当前候选通过。最终结论应绑定不可变源码提交、依赖锁、程序和用户包 SHA-256，由实际本机记录、GitHub Actions 运行和 Windows 操作记录给出。

## 本轮实现范围

- 恢复正常语义候选，保留 cosine 排序、文件聚合和 RRF。保留模型完整性、768 维、有限数值、归一化及黄金向量一致性检查。低相似度候选可能返回，不承诺任意内容都能准确检索。
- 功能测试使用固定小集合覆盖文档、PDF、代码、图片、OCR、语音、环境音和视频，实际运行提取、推理、持久化、重载和生产检索。
- 统一扫描和提取格式规则、500 条查询上限、快捷窗的完整查询上下文，以及按规范化 profile 协调 GUI 单实例。
- 构建 11 个 CPU/GPU 变体并生成 21 个用户文件。ROCm 固定 RDNA4 两个目标，CUDA 采用锁定上游配方，macOS 只构建 Apple Silicon Metal。
- 统一开发入口和外置目录。测试默认执行全部保留用例，局部筛选只用于排查。普通打包不重复生成符号和源码材料。
- CI artifact 仅包含用户包。发布工具按 run、attempt、候选提交及 artifact 摘要获取和冻结成品，只显式上传草稿。

以上是本轮实施范围。各项修复的具体入口和测试映射见 [需求与测试矩阵](requirements-test-matrix.md)，实际成功状态以本轮结果为准。

## 目录与兼容性

新的构建目录按变体及构建配置隔离，不把旧缓存原地改名后继续使用。已有外置历史构建、模型、Qt SDK 和用户配置不属于本轮仓库清理范围。只处理仓库废弃实现及本次明确归属的受控生成物。

产品显示名称、`qcs` profile、模型指纹、协议和数据库 schema 保持兼容。只调整语义候选接受方式不要求用户重建索引。应用卸载保留用户模型、索引和配置。
