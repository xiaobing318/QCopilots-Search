# 容量与性能验收

容量验收分为物理文件遍历、合成向量检索、真实语义质量和故障恢复。四份结果各自说明测量边界。合成向量有高召回率不能推导实际用户文件的语义质量。

## 合成向量基准

`qcopilots-search-benchmark` 使用固定种子流式生成 768 维向量，实际写入 SQLite、构建 ANN、关闭并重新打开，然后与精确 top-20 对照。程序创建唯一的测试子目录，生成物不写入源码树。

CI 使用较小规模执行相同存储路径：

```bash
qcopilots-search-benchmark \
  --profile-dir "$build_root/ci-capacity" \
  --files 3000 --segments-per-file 10 \
  --queries 10 --timings 20 \
  --report "$build_root/reports/capacity-ci.json"
```

当前 Windows 的百万规模命令：

```powershell
$benchmark = Join-Path $buildRoot 'release/bin/qcopilots-search-benchmark.exe'
& $benchmark --profile-dir (Join-Path $buildRoot 'benchmark') `
  --files 100000 --segments-per-file 10 --queries 100 --timings 500 `
  --seed 20261011 --min-free-gib 3 --budget-gib 7 `
  --report (Join-Path $buildRoot 'reports/million.json')
```

`--keep` 保留本次唯一目录用于排查。默认清理由程序在关闭数据库、索引和句柄后执行。预算参数用于当前机器，可在其他机器调整。

要求 recall@20 ≥ 0.95。预热后测量至少 500 次检索，目标为 P95 ≤ 500 ms，单分片后台重建时 P95 ≤ 1 s。报告单独记录 10 次预热与正式计时次数。查询编码、媒体提取和端到端延迟必须另报，不能混入或省略测量范围。基准还包含 10%、1%、0.1% 目录过滤的精确对照、增删改和后台单分片重建查询，报告分别保留其结果。

增删改阶段对每个受影响文件执行生产检索接口的文件过滤查询，核对关键词、向量命中、片段身份和来源版本，并检查被替换或删除的片段已消失。每阶段另执行全局生产检索抽样查询，逐条核对返回片段和当前文件版本。报告分别记录文件过滤查询和全局抽样的次数，并记录全局查询实际使用的 ANN 或精确小子集路径，不能把文件过滤查询描述为全量 ANN 召回验收。正式 CI 使用 30,000 个向量，使全局查询实际进入 ANN，用户自行选择不超过 20,000 个向量时则走生产精确查询路径。

后台重建的时间区间由真正插入图节点的循环内部记录，不包含等待线程启动、序列化或发布。报告保留建图区间和每条查询的起止时间，只使用与实际建图区间相交的查询计算后台 P95。没有实际重叠时，结果不能记为通过，也不会人为等待以延长建图。完整流程在初始建库后还会因增删改多次重建各分片，另有后台重建及故障恢复，因此初始建库耗时不能代表总验收时间。

ANN 使用 16 个分片，图结构参数为 `M=24`、`efConstruction=200`。默认查询预算 `efSearch=4096`，标准检索和可取消检索使用相同值。最初的 512 预算在百万规模首轮实测中得到总体 Recall@20 0.932，未达到门槛。保留图上的只读对照中，4096 是 512、1024、2048、4096 四档里唯一在原 100 条查询与独立固定种子的 40 条查询中均达到 0.95 的预算，两组结果分别为 0.9625 和 0.965。预算选择没有修改向量、查询答案、构建参数或召回门槛。该对照只用于选择通用参数，正式通过仍以完整百万流程及过滤、恢复、500 次计时结果为准。

查询预算不改变持久图结构。旧版本以 512 保存的图可以由新版本读取，并使用当前查询预算，不需要因为该参数变化重建图。

JSON 报告记录 `passed`、`error`、`annEfSearch`、`recallAt20`、聚类/均匀分布召回、`latencyMilliseconds`、构建与重开状态、每条查询和磁盘采样。服务状态同样报告实际 `annEfSearch`。`sampledDirectoryPeakBytes` 是采样峰值，不是连续监测的严格上界。

## 物理文件遍历

`qcopilots-search-tests-file-capacity` 在动态创建的测试根生成真实小文件，验证遍历、修改对账、取消和排除。完整验收需实际生成十万个文件。CI 可运行较小规模，但必须在报告中写明文件数，不能沿用“十万”结论。

通过 `QCOPILOTS_SEARCH_PHYSICAL_FILE_COUNT=100000` 选择完整规模，`QCOPILOTS_SEARCH_DISK_RESERVE_BYTES` 指定磁盘空闲保留量。默认运行生成 1,000 个物理文件，不应把默认结果记为十万规模。

向量基准中的逻辑文件身份不等于真实磁盘文件，所以不能用其 `--files 100000` 参数替代物理遍历验收。

## 语义与故障验收

真实语义集要求至少 1,000 个真实片段、200 条中英有答案查询和独立无答案查询。覆盖文字、OCR、图片、语音、环境声、视频和代码。整体 Recall@10 ≥ 0.90，主要语言与模态分组 ≥ 0.80。数据来源、许可、标注、模型与提取指纹需要可追溯。

故障验收包括增删改、过滤、提交中断、worker 崩溃、磁盘不足和重启恢复。检查返回结果的文件版本，失效版本数量必须为零。普通存储重开用例不能替代中断时刻的故障注入。

容量基准的各个已提交故障阶段使用不同的版本、关键词和向量，恢复后检查本次提交的身份，防止把上一阶段的旧状态误判为成功。未提交事务阶段要求保留上一提交，并检查全表不存在注入的未提交污染值。原始恢复报告同时保留进程退出码、预期和实际身份以及旧版本检查结果。

这四个容量故障点模拟事务和原子发布过程中的进程退出，保留可读取的旧或新 ANN manifest。它们不覆盖 manifest 本身完全丢失或损坏的情况。后者需要根据 SQLite 重建整个 ANN，并可能暂时保留磁盘上的旧分片，额外空间可接近一整套 ANN。因此不能用这四项故障结果声称完全损坏恢复也满足同一 7 GiB 目录预算。

## 磁盘预算与证据

本次 Windows 验收使用现有磁盘，开发 SDK、依赖、模型和编译产物峰值预算约 12 GiB，百万测试目录峰值预算 7 GiB，持续保留至少 3 GiB 可用空间。每阶段和批量写入前检查实际可用空间，空间不足应明确中止并保存错误，不冒险耗尽磁盘。

普通测试、十万文件、百万向量和最终打包分阶段执行，一次只重建一个分片。验收后保留报告、随机种子、指纹、源码提交和最终包，只有本任务创建的可再生产物可被边界校验后清理。

上述数值是本次验收参数，不是应用或测试框架对所有电脑的全局假设。最终结论以实际报告为准。
