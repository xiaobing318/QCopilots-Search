# 架构与进程契约

QCopilots Search 将交互、持久化、提取和推理分开。GUI 与 CLI 使用相同的本地协议，服务负责目录配置、任务状态和数据发布，工作进程处理耗时或可能失败的输入。

```text
  qcs-gui               qcs-cli
     \                   /
             本地 IPC
                |
           qcs-service
          /     |      \
        配置  SQLite  向量索引
                |
            qcs-worker
       提取 / 查询编码 / 多模态编码
```

## 模块边界

| 模块 | 责任 |
| --- | --- |
| `core` | 数据类型、运行目录、配置、模型文件校验、文件目录规则 |
| `runtime` | llama.cpp / mtmd 推理、提示模板、图像预处理、向量契约 |
| `extraction` | 文本、Office、PDF、OCR、图片、媒体和代码片段提取 |
| `storage` | SQLite、FTS、中文分词、FP16 向量、ANN 及结果融合 |
| `service` | 本地 IPC、实例锁、任务调度、状态发布与工作进程生命周期 |
| `app` | Qt Widgets 引导、搜索、筛选、预览、设置和桌面入口 |
| `cli` | 可脚本化的服务命令与诊断 |
| `worker` | 独立提取或推理请求执行 |

共享 `Segment` 与 `SearchHit` 保存路径、类型、文本、来源和定位。PDF 页码、代码行号、Notebook 单元格、媒体时间都使用明确字段，不通过显示字符串反向解析。

文件浏览使用独立的 `FileListEntry`。它只包含文件 ID、路径、文件名、类型、修改时间、源版本和空间标记，不携带片段正文或预览内容。浏览目录和搜索片段是不同的协议操作，不能用空关键词搜索代替文件浏览。

## 运行目录与实例隔离

`RuntimePaths` 集中解析配置、数据库、模型、缓存、日志、临时文件、锁和 IPC 名称。正常运行使用平台标准应用目录，显式 `--profile-dir` 和 `--model-dir` 优先。服务锁及 IPC 名称包含 `qcs` 前缀和实例摘要。

程序使用现有 `qcs` profile 布局，仓库规范名称和 GUI 可执行文件改名不改变该布局。对于更早的旧布局，不自动迁移或回退。显式选择含旧持久化文件的目录时报告不兼容，避免在同一目录另建数据库或绕过旧服务锁。模型内容可经锁定校验后导入，命名变更不改变推理、提取或持久化格式的非路径指纹。

同一规范化配置目录由一个 GUI 主实例和一个服务协调运行。第二次 GUI 启动向已有实例发送受限的激活请求后退出，不再创建会在退出时停止共享服务的第二个主窗口。不同配置目录仍可并行，后台重复启动保持后台状态。多个 checkout、自动化测试及正式应用可以使用不同配置目录同时运行。测试设置 `QStandardPaths::setTestModeEnabled(true)`，同时显式使用独立临时目录，不能只依赖 Qt 的测试模式来实现隔离。

本地协议有版本、请求 ID、消息上限、超时、错误和取消语义。大文件内容不直接放入 IPC 帧。客户端不能仅凭同名本地端口把另一个用户或另一运行目录的服务当作当前实例。

## 配置迁移与两个索引空间

配置版本为 2。`roots/excludes` 管理普通文件，`codeRoots/codeExcludes` 管理代码文件，`includeCode` 控制代码索引是否启用。两套目录和排除规则独立，关闭代码索引保留代码目录设置。同一路径可以在两个空间中具有独立记录，存储身份由规范路径与 `code` 标记共同确定，删除、过滤和续读状态不能只按路径处理。

读取版本 1 配置时，若原来启用了代码索引，则将原目录及排除规则复制到代码空间。原来未启用时，代码目录保持为空。服务在校验后原子保存版本 2，不能因升级扩大用户选择的读取范围。版本 2 同时保存 `pdfOpener` 和 `mediaOpener`，每项包含预设、程序路径及独立参数数组。

SQLite schema 为 3，`files` 新增可为空的 `modified_ms` 和文件级 `kind`，并建立浏览及待补齐元数据索引。升级在事务中执行，保留已有片段、向量和文件版本，不为补元数据强制重新提取所有正文。旧记录的未知修改时间不能伪造为零。服务先扫描核对来源、目录资格和源版本，再补齐元数据与清理确已消失的记录。核对尚未完成时，浏览、搜索或正文读取可明确返回 `metadata_pending`。不可访问目录保留其已存数据，不能把扫描失败解释为整个目录已删除。更新版本创建的 schema 则明确拒绝打开。

## 文件浏览与选中预览

`files.list` 接受 `code`、`kind`、`root`、`limit` 和可选 `cursor`，其中 `limit` 为 1 至 100。结果含 `files`、`nextCursor`、`hasMore`、`browseGeneration`、`metadataPending`，服务另附当前 `visibilityEpoch`。文件 ID、毫秒时间和代次等 64 位值使用十进制字符串传输，避免 JSON 客户端的整数精度丢失。

存储按 `modified_ms DESC, id DESC` 排序。下一页使用上页最后一项的修改时间和 ID 作为 keyset 边界，查询最多读取 `limit + 1` 项判断是否还有结果，不使用不断增长的 offset。每页只持有本次读取的短事务，完成后释放，不为用户停留在页面期间维持数据库快照。游标绑定索引 UUID、浏览代次、规范化筛选条件与服务配置令牌，不允许跨空间、目录或索引复用。

`browseGeneration` 反映文件成员和浏览元数据变化，片段续读、向量发布及无变化扫描不应使它增长。服务的 `visibilityEpoch` 补充目录可访问性和 Git ignore 等可见资格变化。`indexChanged` 携带这两个值，GUI 仅在当前页代次或可见资格确实变化时标记过期。无效游标、过期游标、元数据待核对和存储失败分别返回明确错误，不能作为空列表成功响应。

主窗口空查询每页加载 100 项，提供“加载更多文件”。追加保留当前选择、滚动位置和已经展开的预览。快速窗口空查询最多显示 12 项，不提供分页，用户可刷新或转到完整搜索。普通搜索与快速搜索的列表均仅展示两行文件及定位元信息，不包含正文摘录或内容缩略图。主窗口自动选中首项，再由右侧预览读取或显示该文件。普通文本浏览仅自动读取首批正文，后续通过继续读取按钮加载。

快速窗口转到完整搜索时传递查询、普通或代码空间、文件类型和目录范围。主窗口以这个完整上下文替换旧筛选，避免旧代码空间或目录条件改变快速窗口原有查询的含义。搜索结果数量的 CLI 和服务约束统一为 1 至 500，文件浏览仍使用独立的 1 至 100 分页限制。

查询、目录、类型或空间变化后重新定位首项。无关的语言或外部应用设置变化不丢弃累计页面。刷新同一上下文时结合路径、空间、源版本和命中位置保留选择，不能仅依赖可能复用的文件 ID。游标过期时保留已有列表与预览，禁用继续追加并要求刷新。请求响应还必须匹配当前输入上下文，避免 debounce 期间的旧响应替换用户正在输入的新查询。服务不支持 `files.list` 时明确提示版本不兼容，不静默退回其他操作。

## 索引与查询

SQLite 保存权威文件和片段记录，向量规范化后以 FP16 保存。关键词索引覆盖文件名、正文和 OCR 文本。中文检索结合分词与汉字位置信息，语义检索使用 768 维向量。

向量索引由不可变分片和有界增量组成。数据库版本、文件版本、模型指纹和索引 manifest 共同决定某个候选是否仍然有效。删除或修改后的旧片段不能因为旧 ANN 分片仍在内存中而重新出现在结果里。过滤条件必须影响召回，不能先截断全局 top-k 再过滤而返回错误的空结果。

耗时编码和 ANN 构建在发布锁之外执行。服务协调提交与查询快照，短暂的发布步骤更新代际。后台重建一次处理一个分片，降低磁盘峰值和交互延迟。

候选按精确 cosine 重排，再按文件聚合，与关键词结果采用 RRF 融合。匹配来源随结果返回，以便界面解释文件名、正文、OCR 或语义命中。`SearchHit.score` 表示融合分数，不等同于 cosine。关键词和语义模式分别处理无模型、空结果和部分提取失败。

正式检索不设模态相关性阈值，也不区分生产候选与测试候选。低相似度结果可能进入结果列表，结果出现本身不保证查询有对应答案。模型 SHA-256、向量维度、有限数值、归一化及存储完整性检查继续执行。模型、预处理、embedding 指纹和数据库 schema 保持兼容，这项候选选择调整不要求重建用户索引。功能测试验证真实编码、持久化、重载和正式检索链路，黄金向量检查验证锁定推理实现的数值一致性。

## 提取与推理

扫描和提取路由使用共同的格式定义，代码后缀和 Dockerfile 等特殊文件名按同一规则识别。文本提取保留分块及定位信息。HTML 不加载外部资源，Office 包以 ZIP/XML 读取，RTF 处理编码和控制组。PDF 逐页提取文本并对扫描页执行 OCR。媒体通过与 Qt Multimedia 配套的 FFmpeg 解码，音频采用窗口编码，视频保留时间位置并抽取画面。

推理后端固定 llama.cpp b11461 与 EmbeddingGemma 2 Q8_0。文本与图像、音频最终都进入同一 768 维模型空间。查询编码与索引编码的提示不同，变更提示、缩放或音频窗口需要同步模型空间指纹和回归测试。

每份发行包包含 CPU 后备能力，并按构建变体提供 Vulkan、HIP、CUDA 或 Metal 后端。自动选择同时适用于文本模型和多模态 projector，可用时选择当前包的 GPU 后端，不可用时明确回退 CPU。worker、服务诊断及界面状态报告构建变体、实际后端、设备和回退原因。测试使用严格 GPU 模式时，设备不可用或 GPU 初始化失败必须失败，不能把 CPU 回退计作 GPU 验证成功。

后端模块只从受控安装目录加载。Windows 主程序及 Qt 使用 MSVC，CUDA 和 HIP 后端采用锁定上游配方的独立子构建。最终包只部署主构建的一份 `ggml-base`，插件须与其 ABI 及运行库约束匹配。具体变体、SDK 和运行库部署范围见 [依赖说明](dependencies.md)。托管 runner 没有可用 GPU 时，完整功能测试可验证 CPU 回退，GPU 执行状态仍记录为未实测。

长文档的初始批次、续读状态和失败状态需要持久化。工作进程返回的结果只有在源文件版本、目录配置及模型指纹仍匹配时才可提交。暂停、取消、退出和异常终止后必须释放本次请求的临时文件与子进程。

索引调度分为近期变动、批量首次读取和长文件续读三条队列，按批次采用 4:1:1 轮转，空队列直接跳过。首次大扫描使用批量队列，后续不超过 50 项的变化进入近期队列，队列内部结合截图标记和修改时间安排顺序。新的扫描结果在批次边界合并，不因持续新文件到达无限推迟旧文件或长文件续读。队列令牌使旧版本排队项失效，提交前仍检查来源和配置，队列比例不是耗时比例或毫秒延迟保证。

索引 worker 空闲 60 秒、查询编码 worker 空闲 600 秒后发送有界退出请求，超时才终止对应进程。服务与 GUI 继续运行，下次需要时重新启动 worker。无变化的周期扫描不会延长已开始的空闲期限。新任务在 worker 正在退出时到达，必须等待退出完成再重启，不能把请求写入即将关闭的管道。这些时序有专门用例，实际资源释放和恢复延迟仍以运行报告为准。

## 桌面与平台能力

Qt Widgets 提供共同界面，平台层负责文件打开、编辑器定位、托盘、全局快捷键和登录启动。快捷键使用 Unavailable、Pending、Active、Denied、Failed 状态，界面显示实际绑定并提供显式重试。只有注册确实完成才能显示 Active，平台能力不可用时仍保留主窗口、快速搜索按钮和可用的托盘入口。

Linux 首先通过 `org.freedesktop.portal.GlobalShortcuts` 执行 CreateSession 与 BindShortcuts，处理异步 Response、Activated、ShortcutsChanged 和 Session Closed。实际可用性取决于运行中的 portal 后端及桌面授权，代码没有通过 portal 数字版本号保证所有桌面都支持。只有收到非空的实际绑定描述才报告 Active，建议快捷键不等于用户桌面最终分配的快捷键。

用户拒绝、取消、成功但无绑定或 Session Closed 后，不转用 X11 绕过桌面选择，也不在服务重启时自动再次申请，须由用户显式重试。服务或接口不可用时，只有构建含 XCB、Qt 使用 `xcb` 且运行环境确认不是 Wayland/XWayland，才允许注册 X11 后备快捷键。X11 使用独立连接，在全部 root screen 上检查 grab 结果，处理 CapsLock、NumLock 和长按重复，失败释放已获取的注册。Wayland 环境不能以窗口内快捷键或 XWayland grab 冒充全局快捷键成功。

portal 激活携带的 token 在发出窗口激活信号期间通过 `XDG_ACTIVATION_TOKEN` 转交，并恢复原环境值。这是交接机制，不证明具体 Qt/Wayland 组合已经获得 compositor 的焦点许可。隔离 D-Bus 的 fake portal 测试验证协议和状态机，真实授权、焦点、X11 冲突和桌面重启仍须原生验证。

登录启动只允许默认 profile 和模型目录管理，非默认目录、环境覆盖和 Qt test mode 不能修改真实系统启动项。设置页读取实际状态，只有用户切换选项或使用修复入口才写系统，保存其他设置不触发启动项修改。

| 平台 | 当前登录启动机制 | 必须保留的能力边界 |
| --- | --- | --- |
| Windows | 当前用户 Run 项，指向当前 `qcs-gui` 并传入 `--background` | 配置写入成功不代表已经验证注销后的实际启动 |
| Linux | 用户 XDG autostart `.desktop` 文件，原子写入，Exec 参数直接编码 | 禁用通过 `Hidden=true` 覆盖同名系统条目，桌面是否执行仍需真实登录验证 |
| macOS | macOS 13+ 的 `SMAppService.mainAppService`，要求带 bundle identifier 的 `.app` | RequiresApproval 显示待授权，裸开发程序及较旧系统不能被报告为已启用 |

macOS 通过系统登录启动事件识别后台启动，不替换 Qt 的 Apple event handler。登录启动或 `--background` 默认保留后台托盘运行，若没有可用托盘或显式使用 `--no-tray`，则显示主窗口，避免产生无法打开的隐藏应用。

外部打开通过独立程序与参数数组调用，不经过 shell。PDF 提供 Windows SumatraPDF、Linux Okular、macOS Skim 预设，媒体提供 mpv，也可配置自定义程序和逐项参数。预设请求 PDF 物理页码或媒体秒数，自定义参数支持 `{file}`、`{page}`、`{line}`、`{cell}`、`{startMs}`、`{startSeconds}` 的单次替换，文件名中相同的字面字符不会再次展开。代码编辑器保留独立配置。

系统默认应用只保证尝试打开文件，不保证任意查看器或播放器能够定位。选定应用的程序缺失、平台不符或启动失败会明确报错，不静默改为默认打开，不自动安装外部应用。用户可明确选择系统默认或使用内置预览。发送定位参数成功也只表示应用收到启动请求，最终页码和播放位置要在外部应用确认，尤其是文件已经打开或应用复用现有进程时。当前没有内置 Evince、VLC 或 Preview 的精确定位预设。

首版更新只检查版本并引导用户下载安装，不在后台替换正在运行的程序。安装与升级保留用户数据目录，索引兼容性由 schema 和指纹显式管理。

本文说明模块契约。每项行为的实际实现与验收状态见 [需求与测试矩阵](requirements-test-matrix.md)，不能把架构说明作为测试通过证据。
