# 架构与进程契约

QCopilots Search 将交互、持久化、提取和推理分开。GUI 与 CLI 使用相同的本地协议，服务协调配置、索引和查询，工作进程处理耗时或可能失败的输入。

```text
qcs-gui ──┐
          ├── 本地 IPC ── qcs-service ── 每 GPU 一个索引 qcs-worker
qcs-cli ──┘                  │        ├─ 独立查询 qcs-worker
                             │        └─ 有界预览 qcs-worker
                         配置 / SQLite / 向量索引
```

## 模块与进程

| 模块 | 责任 |
| --- | --- |
| `core` | 数据类型、运行目录、配置、模型校验和文件规则 |
| `runtime` | llama.cpp / mtmd、提示模板、预处理和向量契约 |
| `extraction` | 文本、Office、PDF、OCR、图片、媒体及代码提取 |
| `storage` | SQLite、FTS、中文分词、FP16 向量、ANN 和结果融合 |
| `service` | IPC、实例锁、调度、状态发布和工作进程生命周期 |
| `app` | Qt Widgets 界面、预览、设置和平台集成 |
| `cli` | 可脚本化的服务命令、模型管理和诊断 |
| `worker` | 执行独立提取或编码请求 |

`Segment` 与 `SearchHit` 保存来源和定位，PDF 页码、代码行号、Notebook 单元格、媒体时间使用独立字段。`FileListEntry` 只携带浏览所需的文件元数据，文件浏览不通过空关键词搜索实现。

`RuntimePaths` 为四个进程统一解析目录。父进程向子进程传递相同的绝对 profile/model 路径，服务锁和 IPC 名称绑定用户与规范化 profile。同一 profile 的第二次 GUI 启动激活已有窗口，不同 profile 可以并行。选择规则和登录启动见[配置说明](configuration.md)。

IPC 包含协议版本、请求 ID、长度上限、超时、取消和错误语义。服务验证当前用户及本 profile 的认证 token。Unix socket 使用独立的短路径，避免数据目录长度超出 socket 地址限制。详细方法和传输约束见[服务协议](../src/service/README.md)。

## 配置、存储与索引

配置版本为 3，`modelId` 保存当前模型选择，旧版本缺少该字段时迁移为默认 Gemma。普通文件与代码使用独立的目录和排除规则。关闭代码索引保留代码目录设置。同一路径在两个空间中可以有独立记录，删除、过滤和续读均包含空间标记。普通文件默认发现所选目录及其子目录内所有支持格式，`generalFileRules` 显式保存可选自动过滤条件，规则变化会使目录重新扫描。读取配置时执行版本校验和必要转换，不能因转换扩大用户选择的目录范围。

SQLite schema 为 4，保存权威文件、片段、源版本和 FP16 向量。每个数据库记录模型 ID 和向量维度，打开后维度保持固定。旧 schema 3 索引就地归属默认 Gemma 的 768 维空间，保留已有向量。schema 变更在事务内执行，较新且不受支持的 schema 明确拒绝打开。来源文件尚未核对时可返回 `metadata_pending`，不能伪造修改时间或把不可访问目录当成已删除目录。

关键词索引覆盖文件名、正文和 OCR 文本，中文结合分词与汉字位置信息。语义候选经过 cosine 重排和文件聚合，再与关键词结果用 RRF 融合。`SearchHit.score` 是融合分数，不等同于 cosine。结果不设置最低相关度接受线，低相似度结果可能出现。

向量索引由不可变分片与有界增量组成。文件版本、模型指纹、数据库版本和索引清单共同决定记录有效性。筛选条件参与召回，不能先截断全局结果再过滤。耗时编码与 ANN 重建在发布锁之外执行，提交时再次校验文件身份、设置代际和完整管线指纹。

每款模型保留独立的 SQLite、关键词索引、向量分片和续读进度。默认 Gemma 沿用 `<profile>/index`，其他预设使用 `<profile>/index/models/<model-id>`。切换模型后只运行当前选择的索引与查询，切回时先核对来源元数据，未变文件复用已有结果，离开期间修改、删除或重命名的记录不能作为有效结果返回。模型文件缓存可以共享，索引和关键词结果不能跨模型混用。

模型选择的校验、索引准备或配置保存失败时，保留原模型和索引并返回明确错误。同一模型的权重、提示、预处理或提取管线变化时，服务根据指纹重建受影响的数据。当前索引的管线迁移事务失败会停止相关推理与索引，并保留明确错误。人工修改数据库或绕过指纹校验不属于受支持的更新方式。

## 浏览、搜索与预览

`files.list` 按修改时间和文件 ID 降序分页，每页 1–100 项。游标绑定索引、代次、筛选条件与配置令牌，使用 keyset 边界，不维持跨页面的长期数据库事务。过期游标、元数据待核对和存储错误分别返回错误。

主窗口空查询每页显示 100 项，可继续加载。快速窗口空查询最多显示 12 项，可刷新或转入完整搜索。搜索结果的 CLI 和服务上限为 500。列表显示文件与定位信息，正文由选中后的预览独立读取。

快速窗口转入主窗口时传递查询、普通或代码空间、类型和目录范围。异步响应必须匹配当前查询上下文，避免输入变化期间的旧响应覆盖新结果。刷新尽量按路径、空间、来源版本和命中位置保留选择，游标过期时保留已有内容并要求刷新。

预览在独立 worker 中执行，服务限制并发数量。客户端断线、取消或超时会取消相关工作，未释放的取消请求仍计入并发限制。PDF、代码、Notebook 和媒体预览使用原始定位字段，不反向解析界面文本。

## 提取、推理与调度

扫描与提取共用格式规则。HTML 不加载外部资源或执行脚本，Office 包通过 ZIP/XML 读取，旧 DOC 使用原样 wv2/POLE 与 GNU libiconv。PDF 按页提取，扫描页执行 OCR。媒体由 Qt 配套 FFmpeg 解码，音频按窗口提取并按所选模型能力编码，视频保留实际时间位置。格式边界见[依赖说明](dependencies.md)。

推理使用原样 llama.cpp v0.7.0。模型锁文件提供三款预设，默认 EmbeddingGemma 2 输出 768 维向量，Qwen3-VL-Embedding-2B 和 8B 分别输出 2048、4096 维向量。运行时按模型选择查询与文档提示、pooling 和图像预处理，输出统一做 L2 归一化。模型大小、SHA-256、有限数值、实际维度和保留的黄金向量分别校验，不能用伪造 embedding 替代真实推理。

Gemma 支持文本、图片、视频帧和音频。Qwen 支持文本、图片及视频帧，音频 embedding 请求明确失败，不伪造音频向量。提取与推理能力分别判断，视频有可用画面时仍执行视觉索引，音轨不能被声称为已完成语义编码。具体模型文件与能力见[依赖说明](dependencies.md)。

每个包包含 CPU 后备能力，并按变体提供 Vulkan、HIP、CUDA 或 Metal。后端只从受控安装目录加载，不依赖当前目录或任意插件搜索路径。Windows 窄字符路径调用使用局部 UTF-8 locale，调用完成后恢复线程状态，不修改上游源码或进程全局编码设置。

服务通过隔离 worker 的 `devices` 操作探测当前后端的全部兼容 GPU，不在服务进程中加载驱动，也不为探测加载模型。设备身份由后端和设备 ID 组成，仅缺少 ID 时允许唯一名称匹配。每张卡对应独立进程、模型、上下文和 projector，文本及多模态编码绑定同一设备。显式选择的设备消失或身份歧义时拒绝加载，禁止静默改用 GPU0。没有 tensor split 或卡间通信要求，不改变 embedding 指纹及磁盘索引格式。

索引池按文件批次动态领取任务，单文件不会同时在两个槽位执行，续读保持顺序。每个槽位独立保存请求 ID、超时、活动文件、运行诊断及已完成批次数。单一数据库写线程串行发布，其他设备可继续推理，每个槽位仅持有有界的活动批次和待写结果。目录扫描结果合并前停止新派发并排空活动批次，设置或模型代次变化时取消相关请求，迟到结果仍需通过请求身份、代次和源版本检查。

每张 GPU 独立执行真实计算自检和模型预热。单卡初始化、显存或驱动故障只隔离对应槽位，尚未完成的批次可以重新分配给健康卡。自动模式仅在全部 GPU 不可用时建立一个 CPU 后备槽位，严格 GPU 模式不回退。设备故障在本次会话内隔离，模型重载或服务重启重新探测。查询继续使用独立 worker，避免排在索引任务之后。

`status` 和 `runtime` 事件保留原有运行摘要，新增 `indexDevices` 和 `indexDeviceCounts`。设备项记录身份、显存、`discovered/ready/busy/failed/idle` 状态、当前路径、任务计数、错误和真实 runtime 诊断。`ready` 数量包含正在工作的健康设备，`discovered` 只计 GPU，CPU 后备可单独出现在设备数组。进度日志保存多个活动文件，并兼容旧的单活动文件记录。

索引调度按批次在近期变化、首次读取和长文件续读间采用 4:1:1 轮转，空队列跳过。长文档前缀和续读状态持久化，单文件达到 5000 片段上限时报告部分索引，文件或管线变化、显式重试才重新处理终态。

索引 worker 空闲 60 秒、查询 worker 空闲 600 秒后请求退出，超时只终止对应进程。新任务在退出期间等待进程结束后重启。暂停、取消和关闭都必须释放本次请求的进程、文件和临时目录。

## 桌面集成

Qt Widgets 提供共同界面。平台层处理文件打开、编辑器定位、托盘、全局快捷键和登录启动。Windows 程序资源、Qt 窗口与托盘、macOS bundle、Linux desktop entry 均使用同源的蓝青 Q 图标。

快捷键状态区分不可用、等待、已激活、被拒绝和失败。Linux 优先使用 GlobalShortcuts portal，真实授权与绑定以桌面响应为准。用户拒绝或取消后不绕过选择。仅在确认是原生 X11、Qt 使用 XCB 且 portal 不可用时启用 X11 后备。失败时保留主窗口和快速搜索按钮。

登录启动保存每用户一个 profile/model 目标。Windows 使用 Run 项，Linux 使用 XDG autostart，macOS 使用 `SMAppService.mainApp`。macOS 先确认启动来源，再初始化目录、实例锁和服务。缺少托盘时显示主窗口，避免不可访问的后台应用。

外部打开使用独立程序与参数数组，不经 shell。PDF 支持 SumatraPDF、Okular、Skim 预设，媒体支持 mpv。自定义参数可使用 `{file}`、`{page}`、`{line}`、`{cell}`、`{startMs}` 和 `{startSeconds}`。启动失败明确报告，系统默认应用只保证尝试打开文件，精确定位取决于外部应用能力。

更新检查引导用户下载和安装，不在后台替换运行中的程序。卸载保留用户配置、模型和索引。实际验证范围由对应构建的测试与 CI 结果说明，本文不作为执行通过记录。
